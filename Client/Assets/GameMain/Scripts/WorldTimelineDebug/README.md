# 时间线可操作调试场景

## 启动

正式场景：`Assets/GameMain/Scenes/WorldTimelineDebug.unity`。
主项目能正常编译时，Unity 菜单 `Tools > 世界时间线 > 打开并运行调试场景` 可直接进入。

当前主项目已有缺失依赖的编译错误（HeroComponent、SfxEntity、OneItemData 等），因此同时提供独立工程启动脚本。在仓库根目录的 PowerShell 运行：

```powershell
& .\Client\Tools\Open-WorldTimelineDebug.ps1
```

脚本把 Client 内的核心代码、调试界面和同一场景复制到仓库内 `.timeline-playground`，使用 Unity 2023.2.2f1 打开并进入 Play。不复制旧游戏和插件，不修改正式游戏入口或 Build Settings。独立工程是生成物，修改代码请改 Client 里的源文件；停止并关闭独立工程后重新运行脚本即可同步。

也可以用 Unity Hub 打开已经生成的 `.timeline-playground` 目录，打开该场景，再点击 Play。

如 Unity 安装位置不同：

```powershell
& .\Client\Tools\Open-WorldTimelineDebug.ps1 -UnityEditor '你的Unity目录\Editor\Unity.exe'
```

## 操作

- 左侧是半径10、共331格的六边形地图。内部节点有6个邻居，中心 (0,0) 为最终关卡，外围有60个候选出生点。点击节点查看，再按移动按钮进入相邻点，耗时一年。滚轮缩放、左键拖动平移；全图、本世、天选按钮用于定位。浅蓝边框标出本世可移动的邻格，越接近中心，灵气越浓。
- 修炼一年/五年、等待、提前伪装都是玩家选项。等待玩家选择时世界不会自行流动。
- 主动碰见天选可以加入或离开；加入和死亡后自动加速观察，可暂停、逐年查看或切换速度。
- 右侧列出全部角色、路线和世界日志。历史路线勾选只影响下一局，点击“按勾选路线开始新局”生效。
- 当前角色死亡、加入或世界结束时，自动保留本轮人生记录；下局可选。内存历史库最多15条，单局最多加载10条；停止 Play 后这些个人记录丢失，尚未实现磁盘存档。
- 年份 0 表示元年。界面显示真实战斗后的生命，不使用动画；修炼达到本级经验门槛后自动升级，扣除经验并保留剩余值；升级增加生命、攻击与寿元。

## 三个验证玩法

1. 接力通关：保留默认勾选的三条破仪路线，反复修炼五年。它们第30、60、90年击败 Boss 并死亡，仪式截止年变为65、95、125，天选第100年通关。
2. 灭世：取消三条破仪路线，开始新局，持续修炼；第35年灭世。也可以只取消某一条，观察接力中断。
3. 改命：勾选“改命 A”，开始新局，立即移动 `(0,-10) → (0,-9) → (0,-10)`。玩家第1年清掉 (0,-9) 的怪物并离开，A 第5年抵达后存活，随后尝试寻路追赶天选，途中仍可能战败。若不清怪，A 按本局战斗结果死亡。建议同时保留三条破仪路线，便于观察完整后续。

预置历史同样由 WorldSimulation 实际执行并生成记录，不直接伪造出生后的属性或奖励。改命角色先靠近非最终关卡的天选路线，再追赶天选，避免把最终 Boss 房当作追赶捷径。

## 验证范围

- .NET：49个核心/调试预置场景通过（含六边形、资质累计区间、单次增量反转、经验结转、跨ID历史成长一致性、移动投影与队友冻结）。
- Unity 2023.2.2f1：独立工程实际编译、反序列化场景和相机，通过编辑器验证默认第100年通关、无接力第35年灭世。
- 独立工程 Play：已实际操作修炼、地图选点、移动、战败后自动观察，检查中文显示和日志；此前方格版已验证完整通关；六边形版已在 Play 中实际验证定位、滚轮缩放、拖动、精确选格、相邻移动与战斗，并重置到元年。
- 主项目整体目前仍受旧脚本缺失依赖阻塞；不把独立工程通过等同于正式游戏集成完成。

后台验证命令：

```powershell
& .\Client\Tools\Open-WorldTimelineDebug.ps1 -ValidateOnly
```

报告位于 `.timeline-playground/Logs/WorldTimelineDebugValidation.txt`，Unity 日志位于 `.timeline-playground/validation.log`。


## 等级经验与资质配置

配置源文件：`Config/CultivationLevel.xlsx`，沿用现有四行表头（说明、字段名、类型、中文注释），第5行起为数据。运行 `Client/Tools/Export-CultivationConfig.ps1` 会导出 GameFramework 的 `Client/Assets/GameMain/Data/DataTables/CultivationLevel.txt` 和调试运行时 CSV；独立工程启动脚本已自动调用此导出。CSV 为生成物，请编辑 Excel。
游戏右上角“查看等级经验 / 属性增量 / 资质”可直接查看全部级别；点击角色列表或地图标记可查看该角色的资质。

- `ExperienceToNext`：当前级别升入下一级的经验消耗。默认10、20、40、80、160、320、640、1280、2560；第10级为满级，填0。
- `Level=1`：出生时的属性范围；`Level>=2`：升级进入该级时增加的数值，均为闭区间。
- `Attribute`：Health=生命上限、Attack=攻击、Lifespan=寿元上限。每项独立生成S/A/B/C资质。
- 当前每次升级攻击增量：S90～100、A80～91、B70～81、C60～71。单次允许小概率出现S低于A。
- 出生值留有差距，并逐级校验累计区间：同级基础属性的S累计下限高于A累计上限，A高于B，B高于C。增加级数或调整增量后若破坏保证，会明确拒绝该配置。
- 每次升级独立生成增量，结果由出生时保留的个人参数和目标等级决定。重新载入历史或换实例ID不会重抽。资质不会随升级改变。
- 升级保留原有伤势：增加多少生命上限，就增加多少当前生命，不直接回满。物品和天选吸收属于额外来源，不参与基础资质排序保证。
- 加入天选后不能再修炼成长；天选继续按击杀吸收属性。预置破仪角色与天选从第3级开始，方便调试接力；本世角色第1级出生。
- 默认数值用于验证玩法，尚非最终平衡。修改Excel后先运行导出脚本，再停止并重新进入Play；独立工程需关闭后运行启动脚本重新同步（会自动导出）。

## 存活角色持续显示

每个存活角色有独立标记，不再把同格多人合成一个“史”字。移动中按路段进度显示，队友与天选同行仍分别显示；重叠标记错位排列。视野外的角色在地图边缘显示“外”提示。右侧列表只列存活角色，本局最多12位可同时显示，不需要滚动寻找。结局时保留存活者的最后位置。
