# 轮回选人界面

## 资源

- 原生预制体：`Client/Assets/GameMain/Prefeb/UIPrefab/world_timeline_preparation.prefab`。
- UIFormLogic：`Client/Assets/GameMain/Scripts/UI/WorldTimelinePreparationCtrl.cs`。
- 准备状态接口：`WorldTimelineDebugView.Preparation.cs`，负责本世选择、轮转锁定、路线互斥与开启轮回。
- 分辨率适配：`WorldTimelinePreparationLayout.cs`，只缩放预制体内既有的 1920×1080 布局，不创建控件。
- AI 参考图：`Client/Assets/GameMain/Image/WorldTimeline/Selection/selection_reference.png`。
- 独立人物图集：同目录 `cultivator_portraits.png`，5列×2行，无文字和状态标记；Sprite 以原始图像尺寸切分，避免导入缩放造成坐标错误。
- 面板沿用 `cultivation_ui_atlas.png` 的 Paper / Slate，与轮回地图 UI 共用宣纸、黛蓝与旧金边风格。
- 两次生成均使用内置 image_gen。提示词保存在 `ArtSource/UI/selection-prompt.md`、`selection-portraits-prompt.md`。
- Unity 实际运行截图：`ArtSource/UI/selection-runtime-empty.png`、`selection-runtime-history.png`。

## 接入

`MainTitlePanelCtrl.OpenWorldTimeline(false)` 创建准备态会话，再通过 Game Framework 的 top 组打开选人预制体，并将会话放在命名参数 `userData` 中传入。准备态不要求 Simulation 已创建；与地图 HUD 的打开条件不同。

“开启轮回”调用 `BeginPreparedRun()`，创建模拟、初始化地图与既有地图 HUD，并关闭选人界面。“继续游戏”直接执行原来的 `ResumeUnfinishedRun()`，不会重新选人。结算后地图的“下一世”调用 `PrepareNextLife()`，再次打开同一选人预制体。

正式主菜单流程的旧 OnGUI 选人已关闭；独立诊断场景不受影响。所有按钮、文字、图片、选中状态和已使用遮罩都已保存到 prefab，运行时只绑定和刷新，不生成 UI GameObject。

十张卡位按现有 StartingCultivators 表的顺序绑定；名字、出生点、装备、攻击加成与是否可选来自真实会话数据。十人轮转按保存的轮次计算。一次最多带10条前世，同一修士至多一条，本世修士不允许再作为前世登场。前世列表四条一页，支持翻页和清空。

## 编辑与验证

Unity 菜单 Tools → World Timeline → Build Character Selection Prefab 可重新烘焙，快捷键 Ctrl+Alt+F6。此菜单会重建本预制体，手工调整过布局后请直接编辑 prefab，不必重新烘焙。

运行 bootstrap 并留在主菜单，再执行 Tools → World Timeline → Validate Character Selection Flow。验证使用 Tests/WorldTimeline/obj/Preparation 下独立临时存档，实际走框架加载、原生 Button 回调、地图开局、保存、续玩、结算和下一世。

2026-11-05 最终资产版本的验证：`Tests/WorldTimeline/obj/Preparation/20261105-155450/Validation.json`，16项检查通过。包含空记录、角色切换、已用角色禁用、同身份互斥、路线翻页、初始道具、元年开局、续玩和结算重开。实际截图已检查，无参考图文字混入立绘。未验证打包后的热更新资源清单，发布前仍需按工程现有资源打包流程收集新 prefab 和依赖图集。
